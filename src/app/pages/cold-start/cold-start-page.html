What actually fixes it

  • Keep one instance alive. --min-instances 1 does not make startup faster — it moves it off the critical path of a real visitor. The cost still exists; nobody waits for it.
  • Give the CPU stages more CPU. --cpu-boost raises the vCPU allocation during startup only. It moves the amber bars above and does nothing to the blue ones, because you cannot compute your way through a network round trip.
  • Make the eager work smaller, not the render faster. Shaving 3 ms off a render that already takes 19 ms is invisible next to a {{ format(b.eagerMs) }} startup. Index lazily, fetch secrets in parallel, and drop whatever the first request does not need.
  • Move lazy work into eager work — or accept it. The connection pool opens after the health check passes, so Cloud Run believes the instance is ready while the first visitor is still waiting. Connecting during startup makes the instance honest about when it is actually usable.

Startup weight is configurable: BOOT_PROFILE=off | realistic | heavy. The demo scripts in demo/ drive it from the outside.
